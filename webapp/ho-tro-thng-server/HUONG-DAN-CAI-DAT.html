Cài đặt mới

1 Yêu cầu hệ thống

Hạng mụcYêu cầu
Máy chủ1 máy tính bất kỳ (Windows / Linux / macOS) luôn bật trong giờ làm việc. Không cần máy mạnh — 4 GB RAM là đủ cho một phòng ban.
Phần mềmNode.js phiên bản 22.5 trở lên (khuyến nghị 24 LTS). Đây là yêu cầu bắt buộc vì hệ thống dùng SQLite tích hợp sẵn của Node.
MạngMáy chủ và các phòng ban cùng một mạng nội bộ (LAN / Wi-Fi công ty). Không cần Internet để chạy.
Gói cài thêmKhông cần — hệ thống là Node.js thuần, không phụ thuộc thư viện ngoài, không cần chạy npm install.
Vì sao cần Node 22.5+?Hệ thống lưu dữ liệu bằng SQLite thông qua mô-đun node:sqlite — chỉ có sẵn từ Node 22.5. Nếu Node cũ hơn, máy chủ sẽ báo lỗi và dừng ngay khi khởi động.

2 Cài Node.js

  1. Truy cập https://nodejs.org, tải bản LTS (24.x) cho hệ điều hành máy chủ.
  2. Cài như phần mềm thường: Next → Next → Finish (Windows) hoặc trình cài của macOS.
  3. Kiểm tra: mở WindowsCommand Prompt / Linux·macTerminal và gõ:
node -v

Nếu hiện ra số phiên bản (ví dụ v24.5.0) là đạt. Nếu số < 22.5, hãy gỡ bản cũ và cài lại bản LTS mới.

Ubuntu / DebianCó thể cài nhanh bằng: sudo apt install nodejs npm — nhưng nhớ kiểm tra node -v ≥ 22.5; nếu kho hệ điều hành còn Node cũ, dùng NodeSource hoặc nvm để lấy bản 24 LTS.

3 Chép thư mục & khởi động lần đầu

  1. Chép toàn bộ thư mục ho-tro-thng-server vào máy chủ — ví dụ C:\ho-tro-thng-server (Windows) hoặc /opt/ho-tro-thng-server (Linux).
  2. Khởi động máy chủ:
    # Windows: nhấp đúp file start-windows.bat # Linux / macOS: bash start.sh # Hoặc mọi hệ: node server.js
  3. Cửa sổ sẽ hiện các địa chỉ truy cập, ví dụ:
    • Trên máy chủ này: http://localhost:3000 • Các phòng ban trong LAN mở: http://172.16.10.5:3000
  4. Mở trình duyệt trên máy chủ vào http://localhost:3000 để kiểm tra màn đăng nhập hiện lên.
Để nguyên cửa sổ này chạyNếu khởi động bằng .bat/start.sh, đóng cửa sổ = tắt máy chủ. Để chạy nền bền vững, dùng PM2 ở mục 6.
Lần chạy đầu tạo sẵnỞ lần chạy đầu, hệ thống tự tạo file dữ liệu data.db, các tài khoản mẫu và một ticket ví dụ. Nếu trước đây từng chạy bản cũ lưu bằng data.json, dữ liệu sẽ tự chuyển sang data.db (bản cũ đổi tên thành data.json.imported).

4 Thiết lập mạng

4.1 Cho phép qua tường lửa Windows

Lần đầu chạy, Windows có thể hỏi “Allow access” → chọn Allow / Cho phép (cả Private network). Nếu không thấy hỏi mà máy khác không vào được: mở Windows Defender Firewall → Allow an app và cho phép Node.js, hoặc mở cổng 3000.

4.2 Đặt IP tĩnh cho máy chủ

Nên đặt IP tĩnh để địa chỉ máy chủ không đổi (nhờ IT hoặc đặt trong router). Nếu IP đổi, các phòng ban phải gõ lại địa chỉ mới. Nên tạo bookmark địa chỉ trên máy nhân viên.

4.3 Đổi cổng (nếu 3000 bị trùng)

# Windows: set PORT=8080 && node server.js # Linux/mac: PORT=8080 node server.js
Kiểm tra từ máy khácTrên một máy cùng mạng nội bộ, mở trình duyệt gõ http://<IP-máy-chủ>:3000. Vào được màn đăng nhập là mạng đã thông.

5 Cấu hình ban đầu

  1. Đăng nhập tài khoản quản trị mặc định: admin / admin123. Hệ thống bắt buộc đổi mật khẩu ngay ở lần đăng nhập đầu (tối thiểu 8 ký tự, có cả chữ và số).
  2. Vào menu Người dùng → tạo tài khoản cho từng nhân viên & phòng ban, gán vai trò phù hợp (Điều phối / Nhân viên xử lý / Người yêu cầu / Ban giám đốc).
  3. Vào menu Danh mục & SLA → rà soát và chỉnh: ngưỡng SLA, giờ làm việc, danh mục Loại công việc, Phòng ban, Đội hỗ trợ, Danh mục Dự án, dung lượng tệp đính kèm…
Bảo mật bắt buộcĐổi mật khẩu admin ngay sau lần đăng nhập đầu. Không để tài khoản mẫu ở mật khẩu mặc định trong môi trường thật.

6 Chạy nền tự động với PM2 (khuyến nghị cho vận hành thật)

Với PM2, máy chủ chạy nền (không cần giữ cửa sổ đen), tự bật lại khi lỗi và tự khởi động cùng máy tính.

Cách dễ nhất Windows

  1. Đóng cửa sổ đang chạy node server.js (nếu có) để tránh trùng cổng.
  2. Chuột phải install-pm2-windows.bat → Run as administrator, rồi làm theo hướng dẫn trên màn hình.

Hoặc gõ tay (PowerShell quyền Administrator, tại thư mục app)

npm install -g pm2 pm2-windows-startup pm2 start server.js --name ho-tro-thng pm2 save pm2-startup install pm2 save

Linux·mac tương tự, dùng pm2 startup thay cho pm2-windows-startup:

npm install -g pm2 pm2 start server.js --name ho-tro-thng pm2 save pm2 startup # chạy dòng lệnh mà nó in ra, rồi: pm2 save
Cần Internet lần cài đầuCài PM2 qua npm install -g cần Internet một lần. Sau khi cài xong, máy chủ chạy hoàn toàn nội bộ, không cần mạng ngoài.

7 Sao lưu & khôi phục dữ liệu

Toàn bộ dữ liệu nằm ở 2 nơi (cùng thư mục server.js):

Thành phầnNội dung
data.dbToàn bộ ticket, phát sinh, người dùng, cấu hình & danh mục.
thư mục uploads/File đính kèm thật do người dùng tải lên.

Sao lưu

  1. Tốt nhất tắt máy chủ: pm2 stop ho-tro-thng.
  2. Copy cả data.db và thư mục uploads/ sang nơi an toàn (đặt tên theo ngày, ví dụ backup-2026-08-07).
  3. Bật lại: pm2 start ho-tro-thng.
Nếu copy lúc đang chạyNhớ copy kèm cả data.db-wal và data.db-shm (nếu có) cùng lúc với data.db, nếu không bản sao có thể thiếu dữ liệu vừa ghi.

Khôi phục

Tắt máy chủ → chép data.db và uploads/ bản sao lưu đè vào (xóa data.db-wal, data.db-shm nếu còn) → bật lại.

Nên đặt lịch sao lưu định kỳVí dụ cuối mỗi ngày làm việc. Có thể dùng Task Scheduler (Windows) / cron (Linux) để tự copy data.db + uploads/.

8 Kiểm tra sau khi cài (checklist)

  • node -v ≥ 22.5.
  • Máy chủ khởi động không báo lỗi, hiện địa chỉ truy cập.
  • Mở được màn đăng nhập trên chính máy chủ (http://localhost:3000).
  • Một máy khác cùng LAN vào được bằng IP máy chủ.
  • Đã đổi mật khẩu admin; đã tạo tài khoản cho nhân viên.
  • Đã đặt IP tĩnh & mở tường lửa.
  • Đã cài PM2 (máy chủ tự chạy nền, tự bật khi khởi động máy).
  • Đã sao lưu thử data.db + uploads/ và biết cách khôi phục.
Phần B

Cập nhật khi hệ thống có thay đổi

9 Nguyên tắc an toàn khi cập nhật

Áp dụng cho mọi loại thay đổi: thêm module mới, chỉnh sửa giao diện, vá lỗi hệ thống…

Bản cập nhật chỉ gồm các file mã nguồn (thường là server.js, thư mục public/, các file .bat/.sh, tài liệu). Việc cập nhật thực chất là chép đè file mã nguồn mới lên bản cũ.

Ghi nhớ 3 điềuChi tiết
① Luôn sao lưu trướcCopy data.db + uploads/ trước khi chép đè bất cứ thứ gì.
② Không đụng vào dữ liệuTuyệt đối không chép đè lên data.db và thư mục uploads/ — đó là dữ liệu thật của công ty. Chỉ thay file mã nguồn.
③ Cấu trúc dữ liệu tự nâng cấpBảng / cột / cấu hình mới do phiên bản mới cần sẽ tự tạo an toàn khi khởi động lại — không cần thao tác thủ công, dữ liệu cũ giữ nguyên.
Vì sao nâng cấp không mất dữ liệu?Máy chủ được thiết kế để nâng cấp an toàn: tạo bảng theo kiểu “tạo nếu chưa có”, thêm cột mới bỏ qua nếu đã tồn tại, và tự bổ sung các tham số cấu hình mới mà không xóa cấu hình bạn đã lưu. Dữ liệu ticket/phát sinh/người dùng không bị chạm tới.

10 Quy trình cập nhật chuẩn (từng bước)

  1. Sao lưu trước (bắt buộc). pm2 stop ho-tro-thng rồi copy data.db + uploads/ ra nơi an toàn (đặt tên theo ngày). Giữ lại cả bản zip mã nguồn hiện tại để lỡ cần quay lui.
  2. Nhận bộ file mới (file zip do bên phát triển gửi) và giải nén ra một thư mục tạm.
  3. Tắt máy chủ nếu bản cập nhật có đụng server.js: pm2 stop ho-tro-thng. (Nếu chỉ đổi giao diện public/ thì có thể không cần tắt — xem mục 11.)
  4. Chép đè file mã nguồn mới vào thư mục đang chạy: server.js, thư mục public/, các file .bat/.sh, tài liệu…
    Giữ nguyên data.db (và data.db-wal, data.db-shm) cùng thư mục uploads/. Nếu bản zip mới không kèm hai thứ này thì càng yên tâm — cứ chép đè phần còn lại.
  5. Bật lại máy chủ: pm2 restart ho-tro-thng (hoặc pm2 start ho-tro-thng nếu đã stop). Lúc này bảng/cột/cấu hình mới (nếu có) tự được tạo.
  6. Trên trình duyệt của người dùng: nhấn Ctrl + F5 để tải lại giao diện mới (bỏ qua cache).
  7. Kiểm tra theo checklist mục 13.
Cập nhật giao diện thì rất nhanhFile giao diện (public/index.html) được máy chủ gửi ra với chế độ “không lưu cache”. Vì vậy nếu chỉ đổi giao diện, sau khi chép đè, người dùng chỉ cần Ctrl + F5 là thấy bản mới — thường không cần khởi động lại máy chủ (nhưng pm2 restart cho chắc cũng không sao).

12 Khôi phục nhanh khi cập nhật lỗi (rollback)

Nếu sau khi cập nhật máy chủ không chạy hoặc phát sinh lỗi:

  1. Xem lỗi trước: pm2 logs ho-tro-thng — thường chỉ rõ nguyên nhân (ví dụ Node quá cũ, thiếu file).
  2. Quay lui mã nguồn: chép đè lại bộ file bản cũ (từ zip đã giữ ở bước 1 mục 10) lên thư mục đang chạy.
  3. Khôi phục dữ liệu nếu cần: nếu nghi dữ liệu bị ảnh hưởng, tắt máy chủ, chép data.db + uploads/ từ bản sao lưu đè vào (xóa data.db-wal, data.db-shm nếu còn).
  4. Bật lại: pm2 restart ho-tro-thng và kiểm tra lại.
Mẹo vận hànhMỗi lần cập nhật, giữ lại bản zip mã nguồn cũ kèm ngày tháng (ví dụ ho-tro-thng-server-2026-08-01.zip). Khi cần quay lui chỉ việc giải nén bản đó — nhanh và chắc chắn.

13 Kiểm tra sau khi cập nhật (checklist)

  • Đã sao lưu data.db + uploads/ trước khi chép đè.
  • pm2 list — máy chủ ở trạng thái online.
  • Mở được màn đăng nhập; đăng nhập tài khoản thật thành công.
  • Dữ liệu cũ còn nguyên: danh sách ticket, người dùng, cấu hình đúng như trước.
  • Đã Ctrl + F5; giao diện hiển thị bản mới.
  • Tính năng mới / phần vừa vá hoạt động đúng như mong đợi.
  • pm2 logs không có lỗi đỏ lặp lại.

14 Các lệnh PM2 thường dùng

LệnhTác dụng
pm2 listXem máy chủ đang chạy không (online/stopped).
pm2 logs ho-tro-thngXem nhật ký / lỗi theo thời gian thực.
pm2 restart ho-tro-thngKhởi động lại (dùng sau khi cập nhật server.js).
pm2 stop ho-tro-thngTạm dừng (dùng trước khi sao lưu / chép đè).
pm2 start ho-tro-thngBật lại sau khi stop.
pm2 delete ho-tro-thngGỡ khỏi PM2 (không xóa dữ liệu).
pm2 info ho-tro-thngXem chi tiết, gồm đường dẫn file server.js đang chạy.
Cập nhật xong mà không thấy đổi?Kiểm tra pm2 info ho-tro-thng để chắc chắn PM2 đang trỏ đúng thư mục bạn vừa chép đè. Nếu trỏ nhầm thư mục khác, chép đè vào đúng chỗ đó hoặc pm2 delete rồi pm2 start lại từ thư mục đúng.
